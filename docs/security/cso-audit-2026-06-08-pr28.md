## Verification gates (from brief)

### Gate 1 — Phase 1 Attack Surface Census

**Brief asked:** "Has PR #28 added any new HTTP endpoints? No, but the LiveStatus component now makes client-side fetch calls to `/api/health` and `https://sepolia.base.org`. Verify these are appropriate for client-side use (no auth required, no PII returned)."

**Verified:**

- No new server-side route handlers added in PR #28 (`git diff main..HEAD --name-only` shows zero new files under `src/app/api/`).
- `src/app/client.tsx:55` — `fetch("/api/health")`. Confirmed at `src/app/api/health/route.ts:144-186`:
  - Returns `checks: { encKeyConfigured, postmanConfigured, rpcConfigured }` as Booleans only (lines 146-148). No values. No PII. Audit comment at `route.ts:10-15` explicitly states "NEVER returns the actual key/secret values, only boolean presence. NEVER logs env values, even partially."
  - Returns chain state (`blockNumber`, `anonymitySet`, `latestAspRoot`, `entrypoint`, `privacyPool`) — all public on-chain data.
  - Returns `git: GIT_SHA` (7-char short SHA) — public via the GitHub repo URL also returned by `/api/facilitator/supported`.
  - Returns `version: "zBase"`, `stack: stack.label` — branding strings, not secrets.
  - No auth required (intentional — it's a health endpoint for external monitors per the documented contract at `route.ts:3-23`).
  - Zero `console.log` statements (verified by grep — no output). Safe to hit on every landing-page load.
- `src/app/client.tsx:69` — `fetch("https://sepolia.base.org", { method: "POST", ... eth_call ... })`. This is a direct browser-to-public-RPC call:
  - Read-only `eth_call` with hardcoded target (`USDC` token address `0x036CbD...DCF7e`) and hardcoded calldata (`balanceOf(TREASURY)` where `TREASURY = 0xDbAA...0f21`).
  - Returns the treasury's USDC balance, which is already public on BaseScan (anyone can read it).
  - **Privacy note:** the user's IP is exposed to `sepolia.base.org` (Conduit/Coinbase). This is the same exposure as anyone using Base Sepolia with MetaMask's default RPC; not a novel leak. Importantly, no zBase user identity or transaction-specific data is sent. Acceptable for a public landing page.

**Verdict:** PASS at 9/10 confidence. Both fetches are appropriate for client-side use, return no PII, require no auth.

### Gate 3 — Phase 9 A05 (Injection)

**Brief asked:** "The LiveStatus component uses `fetch()` with hardcoded URLs. Confirm no user-controlled input flows into the URLs."

**Verified at `src/app/client.tsx:49-98`:**

- The `LiveStatus` component takes **zero props** and reads **zero React state from parent components**. It is self-contained.
- Both `fetch()` URLs are string literals (`"/api/health"` and `"https://sepolia.base.org"`).
- The POST body to `sepolia.base.org` is a JSON object built from compile-time constants:
  - `TREASURY` and `USDC` are `const` declarations inside the `useEffect` callback (lines 66-67).
  - `callData` is a string concatenation of three string literals: `"0x70a08231" + "000000000000000000000000" + TREASURY.slice(2).toLowerCase()` (line 68). `TREASURY` is a const, `slice()` is pure, `toLowerCase()` is pure. No user input flows here.
- Response handling at lines 79-88 parses `d.result` as a hex string via `BigInt()` (line 82). `BigInt()` of a malformed string throws — caught by the surrounding `.catch(() => {})` at line 88. No injection vector via the response either.

**Verdict:** PASS at 10/10 confidence. The fetch URLs and bodies are fully static. No A05 risk.

### Gate 4 — Phase 9 A02 (Security Misconfiguration)

**Brief asked:** "Confirm the API response shape change (removing `yield` key, adding `roadmap` key) doesn't break any consumers in a security-relevant way."

**Verified at `src/app/api/facilitator/supported/route.ts:34-52`:**

- The change removes a top-level `yield` object (previously `{ enabled: true, protocol: "Morpho Blue", note: "..." }`) and replaces it with `roadmap: { yield: { status: "scaffolded", ... } }`.
- **Security-relevant consumers checked:**
  - The endpoint is GET-only (no POST handler — flagged as `FAC-P1-1` in the morning rerun, persistent).
  - `src/lib/facilitator-authz.ts` exports `pricingStructure()` which is called at line 75 of the route — unchanged shape.
  - The endpoint is consumed by x402 clients for discovery. Removing `yield` means clients that previously relied on it would now see `undefined`. Per JS semantics, this fails open (the client sees "no yield" instead of "yield available"), which is the **correct** direction for a false-claim fix — clients can no longer be misled.
  - No authorization or rate-limiting logic depends on the `yield` key. Verified by grep: zero references to `.yield` or `["yield"]` outside the route file itself.
- The new `roadmap.yield.status: "scaffolded"` is a self-documenting downgrade signal. Honest disclosure replaces an inaccurate claim, which is *strictly better* from a regulatory/compliance posture.

**Verdict:** PASS at 9/10 confidence. The shape change is a security-positive truthfulness fix, not a regression.
