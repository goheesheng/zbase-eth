How zBase works

An AI agent deposits USDC into a privacy pool, then pays any x402 endpoint via a Groth16 ZK proof relayed by the facilitator. The agent's wallet never appears in the settlement. Idle deposits earn yield (Kamino on Solana, Morpho on Base) until the next withdrawal needs them.

The flow — four actors, six steps

A

Agent Buyer

Your AI agent — trading bot, MEV searcher, LLM caller, anything that pays via x402.
Step 1 · One-time, public
Deposit USDC into the pool. Hash a commitment from (nullifier, secret, value) and submit it on-chain. Save the secrets locally — they're the keys to withdraw.
Step 2 · HTTPS
Call any paid x402 endpoint. Server responds HTTP 402 with a price quote.
Step 3 · HTTPS
Send deposit secrets + payment intent to facilitator /settle. (Secrets never touch the chain.)
Step 6 · Retry
Retry the paid endpoint with X-Zx402-Settlement: <txHash>. Server checks its cache, returns 200 OK with the real data.
F

Facilitator zBase server

Drop-in x402 facilitator. Generates the ZK proof and relays the on-chain transaction. The piece you integrate.
Step 4 · ZK proof
Generate Groth16 proof (snarkjs, ~2.5s). Proves four things about the deposit — without revealing which deposit.
Step 5 · Relay
Submit relay_withdrawal(proof, recipient) to the on-chain program. The facilitator pays gas, not the agent.
Cache
Store the confirmed txHash in a server-side cache so the merchant can recognize the private settlement.
P

Privacy Pool On-chain program

Anchor program on Solana (Privacy Pools fork on Base). Verifies proofs, marks nullifiers, transfers USDC out.
On deposit
Poseidon-hash commitment, insert into LeanIMT Merkle tree. Update on-chain root.
On relay
Verify Groth16 on-chain (148K CU of 200K budget) · check ASP root · mark nullifier PDA · enforce recipient binding.
Settle
Pool vault → recipient ATA. Transaction's sender = pool, not the agent.
Y

Yield Market Kamino · Morpho

Idle deposits don't sit still. Pool supplies USDC to a lending market between settlements.
Between settlements
Admin tick: supply_to_kamino idle USDC → earn ~4–9% APY in kTokens.
During relay
If pool's idle USDC < payout, program redeems from Kamino in the same instruction. Yield accrues to depositors.
On withdraw
Depositor's payout = principal + proportional yield. Both invisible inside the pool.

What the ZK proof actually proves

One Groth16 proof, four simultaneous claims

The facilitator can't generate a valid proof unless all four claims are true. Anyone can verify the proof in 148K compute units on-chain — but the proof reveals nothing about which deposit it corresponds to.

1
Membership. "I own some commitment in the pool's Merkle tree." (Doesn't say which.)
2
Compliance. "My deposit is inside the ASP-approved subset." (Not Tornado — Vitalik's design.)
3
No double-spend. "My nullifier has never been used." (Pool marks it on settle.)
4
Recipient binding. "This proof is bound to this recipient and amount." (Relayer can't redirect funds.)

What's revealed vs hidden

After verification the on-chain world learns just enough to settle — and not a single bit more.

✓ Revealed
Recipient address · Payout amount · Nullifier (used once) · "Some deposit funded this"
✗ Hidden
Which deposit · Depositor wallet · Deposit amount · Deposit timing · Any history link

What the on-chain settlement looks like

Standard x402 public

Agent's wallet signs the transfer. Anyone watching the chain learns who paid whom, when, and how much.

// block 461358659 From: 0xAgent…7f2a (your bot) To: 0xProvider…b1c4 (Anthropic) Amount: 1.00 USDC // indexed by 8 wallet trackers ✗

zBase settlement private

The pool signs the transfer. The agent's wallet is nowhere in the transaction. The link between buyer and payment is broken.

// block 461358923 From: zBasePool…9eA1 (facilitator) To: 0xProvider…b1c4 (Anthropic) Amount: 1.00 USDC // nullifier marked, proof verified ✓

Integration · one URL, zero agent code changes

Change your facilitator URL. That's it.

Any x402 agent — AgentCash, OpenClaw, Claude Code, your own — speaks the standard x402 protocol. zBase is a drop-in facilitator: same /supported, /verify, /settle endpoints, with a privacy layer behind them.

// before
const facilitator = "https://api.cdp.coinbase.com/x402";

// after — privacy by default
const facilitator = "https://zbase.xyz/api/facilitator";
